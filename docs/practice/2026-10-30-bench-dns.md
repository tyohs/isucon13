# s2 から s1 へベンチを実行する

対象: ISUCON13、matsuu/aws-isucon の練習環境、Node.js 実装。

- s1: `172.31.2.18`。アプリ・DB・DNS。
- s2: `172.31.0.14`。ベンチマーカー。

## 実行

他の人の反映・ベンチと重ならないタイミングで、s2 の isucon ユーザーから実行する。
初期化処理で s1 の DB データと DNS ゾーンが初期化される。

```sh
cd /home/isucon
./bench run --enable-ssl --nameserver 172.31.2.18
cat /tmp/result.json
```

## 設定の管理元

`s1/home/isucon/env.sh` の `ISUCON13_POWERDNS_SUBDOMAIN_ADDRESS` を
`172.31.2.18` にする。デプロイはこのファイルを s1 の `/home/isucon/env.sh`
へコピーするため、サーバー上のファイルだけを編集すると次の反映で戻る。
この修正を含まないブランチは、main の修正を取り込んでからデプロイする。

Node.js は起動時にこの値を読み、新規ユーザーの DNS レコードに使う。
`POST /api/initialize` は `webapp/sql/init.sh` を経由して
`webapp/pdns/init_zone.sh` を実行し、その時点の `/home/isucon/env.sh` を読んで
DNS ゾーンを作り直す。設定変更後は稼働中の `isupipe-node.service` へ反映する。

確認時は設定ファイルの該当項目と DNS の回答を照合する。

```sh
grep '^ISUCON13_POWERDNS_SUBDOMAIN_ADDRESS=' /home/isucon/env.sh
dig @127.0.0.1 pipe.u.isucon.local A +short
```

どちらも `172.31.2.18` を示すこと。

- 管理元の修正前の main は `da8601a`。検証時のサーバーのアプリコードは

  アプリコードを維持し、s1 の DNS アドレス設定だけを反映した。
- s1・s2 のデプロイロックを取得し、開始前に両ホストでベンチプロセスがないことを確認した。
- s1 の管理元ファイルと実際の `/home/isucon/env.sh` を修正し、稼働中の
  `isupipe-node.service` を再起動した。ベンチ開始時の接続に使う `pipe` の
  A レコードも更新した。
- s2 から s1 に対して 16:37:46–16:39:31 JST に実ベンチを実行。
  所要時間 104.427 秒、`pass: true`、スコア 3444、実装言語 `node`、
  名前解決成功数 2318。初期化・整合性チェック・負荷走行・最終チェックが完了した。
- 一般エラーとして livecomment の report API の HTTP 404 が4件記録された。
  最終判定は成功。DNS の許可先不一致は発生していない。
- 16:40 JST に、s1 の管理元ファイル・実際の設定ファイル・稼働中 Node.js の環境変数・
  `pipe.u.isucon.local` の DNS 回答が、すべて `172.31.2.18` であることを再確認した。
- 生ログ・結果・時刻は s2 の `/tmp/isucon13-bench-dns-01a18b86/` に保存した。
  ベンチ結果は `/tmp/result.json` にも出力される。ログ本体は Git に含めない。
